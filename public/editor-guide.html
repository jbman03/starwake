1. The idea

Everything in Starwake (every ship, port, system and story) is a record: a small block of named values with an id. A plug-in is a file holding records of your own:

  • A record with a new id is added to the game.
  • A record with the id of a game record replaces it, which is how you change something that already exists. For example, you can give the Kestrel more armor, or add a lane to an existing system.

You never start from nothing. You copy a record from the game that is close to what you want, then change it. The Editor checks your work as you type, and won't let you install a plug-in that would not load. The game itself always keeps working.

Quickest start: open the Editor and press Load the sample. It is a complete small plug-in: a system called Thornwick, its port, a ship and an outfit. Click through each type to see how they fit together.

2. A tour of the Editor

Open it from the game's main menu (Plug-ins → Open the Editor) or go to editor.html next to the game. From top to bottom:

  1. Details: your plug-in's Id (lowercase letters, digits and dashes, like rimward-traders), Name, Version, Author and Description. Players see these on their Plug-ins screen.
  2. Record types: Ships, Outfits, Goods, Systems, Ports, Governments, Market events, Mission types, Encounters and Story missions. The number in brackets is how many of that type your plug-in has.
  3. Your records (left): the records of the chosen type. Click one to edit it.
    • Copy a … from the game: a dropdown of every game record of that type. Picking one copies it into your plug-in with a new id, such as kestrel-2.
    • Delete record: removes the selected record from your plug-in. The game's own record is not affected.
  4. Form / JSON (right): two ways to edit the selected record.
    • Form gives every simple value its own box. Numbers, text and on/off are plain fields, and anything that names another record (a system, government, ship, port or good) is a dropdown.
    • JSON shows the whole record as text. Lists and nested parts, such as a port's market, a ship's loadout or a story's steps, are edited there.
  5. Problems: updated as you type. Each line names the file and the field, for example ships.json: hawk.maxSpeed: Too small. When it says No problems: this plug-in would load, you are done.
  6. Map (Systems only): every star system and lane. Your systems are drawn bright blue.
  7. Buttons:
    • Install in the game: puts the plug-in on the game's Plug-ins screen, turned on.
    • Export file: saves your-id.starwake.json to share.
    • Import file: opens a plug-in file to keep editing it.
    • Load the sample: opens the sample plug-in.
    • New plug-in: starts over.
Your work is kept in this browser automatically, so you can close the tab and come back. To move it to another device, or as a backup, use Export file.

3. Walkthrough: your first ship

  1. Open the Editor. In Details, set the Id to my-first-pack and the Name to My First Pack.
  2. Click Ships. In Copy a ship from the game…, choose kestrel. A record kestrel-2 appears and opens in the Form.
  3. In the Form, change:
    • id to hawk. Every id must be unique in the whole game.
    • name to Hawk Interceptor.
    • price to 82000, maxSpeed to 480 and armor to 120.
    • description to a sentence or two of your own.
  4. Check Problems. It should say No problems. If not, see Problems and fixes.
  5. Press Install in the game, then reload the game.
  6. Find the ship: the copied Kestrel is sold by Concord shipyards (soldBy: ["concord"]), so land at a Concord port with a shipyard, such as Vanterre in Tessaly. The Hawk is in the list.
To sell your ship somewhere else, edit soldBy (governments) or add soldAt (a list of port ids) in the JSON view. With neither, any shipyard whose tech tier is at least the ship's techTier sells it.

4. Walkthrough: a new star system with a port

A system needs a place on the map, lanes to its neighbours, and usually a port. Here is how to add Hollowmere Reach next to Skerry.

  1. Click Systems and copy skerry. You get skerry-2, already selected.
  2. In the Form, set:
    • id to hollowmere-reach and name to Hollowmere Reach.
    • government to the faction that owns it (for example independent).
    • jumpDistance (how far from the star you must fly before jumping, 1500–2200 is usual) and starRadius (the star's size).
  3. In the JSON view, empty its lanes: "links": []. A copy would otherwise claim Skerry's lanes.
  4. Place it: on the Map, with your system selected, click an empty spot near Skerry. The system moves there.
  5. Add a lane: click Skerry on the map. A bright lane appears. Lanes run both ways in the game, so the Editor also copies Skerry into your plug-in with the new lane added. Click Skerry again to remove the lane.
  6. Click Ports and copy skerry-light. Set:
    • id to hollowmere-dock and name to Hollowmere Dock.
    • systemId to hollowmere-reach, from the dropdown.
    • techTier to a value from 1 to 5. It decides what the shops can sell.
    • fuelPrice to the cost per unit (core worlds are about 2, the fringe 3–5).
    • kind to planet, moon or station, and a description.
  7. In the JSON view, check:
    • pos: where the port sits in the system, about 300–900 from the centre.
    • services: any of exchange, missions, shipyard, outfitter and bar.
    • market: which goods it trades and at what level, low (cheap), med or high (pays well).
  8. When Problems says No problems, install it and reload. Open the star map: Hollowmere Reach is next to Skerry.
A copied port keeps flags such as hub or dumpSite. Delete them in the JSON if your port shouldn't be a tech hub or a garbage-run destination.

5. Walkthrough: an outfit sold only at your port

  1. Click Outfits and copy something of the right kind:
    • armor-plate for armor, or shield-booster for shields.
    • light-blaster for a gun, or lance-beam for a beam.
    • cargo-pod for hold space, or fuel-tank for fuel.
  2. Set its id, name, price and description, plus these:
    • space: tons of outfit space it uses.
    • max: how many one ship can fit.
    • techTier: the lowest port tier that can sell it.
  3. In the JSON view, change the effect. Armor has {"armor": 60}, and a gun has damage, rate, speed and range. Keep the same keys as the outfit you copied. The category decides which keys an effect needs.
  4. To sell it only at your port, add "soldAt": ["hollowmere-dock"], remove any soldBy, and make sure that port has an outfitter.

6. Walkthrough: a new trade good

  1. Click Goods and copy food. Set:
    • id (for example saltglass), name and description.
    • basePrice: the middle price, in credits per ton.
  2. A good is only traded where a port lists it. Edit two or more ports (copy game ports to change them) and add your good to their market in the JSON view:
    • "saltglass": "low" where it is made and cheap.
    • "saltglass": "high" where it sells well.
  3. Optional:
    • "origin": "a-port-id" makes it a unique good from one port.
    • "illegalIn": ["concord"] makes it contraband in that government's space.
Replacing a game port (same id) to add your good to its market is fine. Your copy replaces the game's port while your plug-in is on.

7. Walkthrough: an in-flight encounter

Encounters are the short cards that pop up between landings: a hail, or a site floating in space.

  1. Click Encounters and copy stranded-passenger.
  2. Set:
    • id, plus the title and text shown on the card. The text can use {ship}, {system} and {pilot}.
    • kind: hail (a radio call) or site (something in space to fly to).
    • weight: how often it comes up compared with the others (most are 5–10).
  3. In the JSON view, edit choices, one to three buttons. Each has a label and a list of outcomes:
    • {"type":"credits","n":500} (a negative number takes credits away).
    • {"type":"cargo","good":"food","tons":5} (negative hands cargo over).
    • {"type":"fuel","n":100}.
    • {"type":"message","text":"..."}, the line shown after the choice.
    • {"type":"rumour","text":"..."}, a note in the Mission Log.
    • {"type":"reveal","systems":["id"]}, which charts systems on the map.
    • {"type":"mission","missionType":"ferry"}, which hands the pilot a job.
    • {"type":"flag","flag":"my-flag"}, which remembers something for later stories.
    • {"type":"standing","government":"concord","level":"friend"}.
  4. Optional:
    • A choice can need something first: "needs": {"credits": 200}, or {"cargo": {"good":"food","tons":1}}, or {"flag": "x"}.
    • "when" limits where and when the encounter appears: minDay, governments, systems, tiers, requiresFlag and notFlag.
    • "once": true means it happens only once.

8. Walkthrough: a story mission

Story missions are offered in a bar or by a hail, run in steps, and pay out at the end. The best place to start is a side mission, such as s1-missing-courier.

  1. Click Story missions and copy s1-missing-courier. Set:
    • id and title.
    • arc: keep side. The main, concord and reach arcs belong to the game's own storyline.
    • chain: a short name of your own.
    • declinable: true.
  2. In JSON, set the giver (name and title), and where it is offered:
    • "offer": {"where": "bar", "ports": ["hollowmere-dock"]}.
    • Optional: minDay, requires (flags the pilot must have), notFlags and standing.
  3. Write the text (the offer, as the giver tells it) and the acceptText (what they say when the pilot takes it).
  4. Write the steps. Each step has a kind and a text for the Mission Log:
    • go: fly to a system.
    • land: land at a planet (a port id).
    • deliver: carry cargo ({"name","tons"}) to a planet, optionally within deadlineDays.
    • ferry: carry passengers to a planet.
    • scan or find: a site ({"label"}) in a system. A find site stays hidden until the pilot is near.
    • meet: a ship ({"name","shipId","government"}) hails the pilot in a system, with a card of choices like an encounter.
  5. Set onComplete, the outcomes when it's done (usually credits, a message, and a flag that a later mission can require). Optionally set onFail as well.
To make a story with several missions, have each mission's onComplete set a flag, and make the next mission's offer require that flag. That is how the game's own arcs are built.

9. Field reference

Ships

FieldMeaning
id, name, descriptionUnique id; what players see.
roleWhat kind of ship it is (starter, courier, scout, freighter, heavyFreighter, liner, interceptor, corvette, trader, carrier); traffic uses it.
hullIts silhouette: pod, dart, wedge, hauler, liner, carrier or fighter.
price, techTierCost in credits; the lowest shipyard tier (1–5) that sells it.
turnRate, acceleration, maxSpeedDegrees per second; how quickly it speeds up; top speed.
shields, armorHow much damage it takes; shields recharge, armor doesn't.
cargo, passengers, fuelCapacityHold tons; berths; fuel units (100 a jump).
outfitSpace, crew, radiusTons for outfits; crew complement; size on screen.
loadoutThe guns it comes with (outfit id → count).
soldBy, soldAt, uniqueGovernments or ports that sell it; sold only once.

Systems and ports

FieldMeaning
mapPosIts place on the star map (use the Map to set it).
linksLanes to neighbouring systems (use the Map; both ends must list each other).
governmentWho owns it: concord, free-reach, independent, unlit, tideward (or one you add).
jumpDistance, starRadius, hazardsHow far out a jump can start; the star's size; notes shown on the map.
systemId, pos, radiusA port's system, its position in that system, and its size.
techTier, fuelPrice, kind, servicesShop tier 1–5; cost per fuel unit; planet, moon or station; what it offers.
marketGoods traded and their price level (low, med, high).

Outfits and goods

FieldMeaning
category, effectWhat the outfit is and what it does (keep the effect keys of what you copied).
space, max, price, techTierTons used; most per ship; cost; lowest port tier.
basePriceA good's middle price per ton.
origin, illegalInA good made at one port only; governments that outlaw it.

10. Problems and how to fix them

The Problems list says…What to do
…: Too small / Too big / Invalid inputThat field's value is out of range or the wrong kind (text where a number goes). Check the field it names.
unknown system "…" / unknown planet "…"A reference names an id that doesn't exist. Pick it from the Form's dropdown, or add that record too.
no port sells thisNo shipyard or outfitter can sell it: lower its techTier, fix soldBy/soldAt, or give your port the right service.
not sold at any "…" hubItems with soldBy must be sold at one of that government's tech hubs too; remove soldBy or use soldAt.
links / lane problemsEach lane must be listed on both systems: use the Map to add lanes and it does both ends.
startShipId must be the lowest-priced shipA ship cheaper than the starter shuttle (10,000 cr) is not allowed; raise its price.
A record is an object with an "id".The JSON lost its "id" line or its outer { }; put it back.
Not valid JSON yetA missing comma, quote or bracket in the JSON view. The message gives the position.

11. Testing and sharing

  1. Test: press Install in the game and reload the game. On the main menu, Plug-ins lists it as Active. Start a new pilot or load one and go and find your work.
  2. Change and retest: edit in the Editor, press Install in the game again (it updates in place) and reload the game.
  3. Turn it off: on the Plug-ins screen, Turn off then Restart now. Note that a pilot who bought your ship can't load while your plug-in is off.
  4. Share: press Export file and send the .starwake.json file. Others open Plug-ins → Import plug-in in the game. A file that wouldn't load is refused with the reason.
  5. Several plug-ins: they load in the order installed; if two change the same record, the later one wins.
Plug-ins can add and replace records, but they can't delete the game's records or change its rules (combat, law, prices and so on). That keeps every plug-in safe to try.
